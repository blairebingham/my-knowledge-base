# Organizing System Analysis: Breaking Bad Fandom Wiki

For this assignment I chose to look at the **Breaking Bad Fandom Wiki**, which is a huge fan-run digital collection that documents everything in the "Gilliverse" (Breaking Bad, Better Call Saul, and El Camino). 

---
## Primary Resources Being Organized 

The primary resources on this site are a mix of fictional universe lore and real-world production data. The biggest focus is on narrative content. The wiki organizes individual articles for characters (like Walter White or Jesse Pinkman), specific locations (like the A1A Carwash), and key plot items (like the Lily of the Valley plant). Alongside these fictional entries, the site organizes real-world resources like episode transcripts, crew directories, cast filmographies, and behind-the-scenes promotional galleries.  

---
## Primary Interactions Supported

The system is built to handle three main user interactions: quick fact-checking, deep research, and casual browsing. Many users visit for fast fact-checking, like looking up what episode a character died in or verifying an actor's name. It also supports deep research for fans who want to track complex timelines or character relationships across multiple seasons. Finally, the site is perfect for casual lateral browsing. Because everything is heavily linked, a user can start by looking up a specific episode and end up reading about a background prop twenty minutes later.

---

## Classification System and Effectiveness 

The wiki uses a hybrid classification system that combines hierarchical navigation with faceted elements, and it is incredibly effective for for its audience. 

The main navigation bar at the top of the site relies on a traditional hierarchical structure. It forces you down a strict tree path based on media types (e.g., TV Shows → Better Call Saul → Season 1 → Episode Guide). This is perfect for users who want a structured, top-down approach to be able to find a specific piece of media. 

However, once you click on an actual article, the site shifts to a faceted system. Every character page features an "Infobox" on the right side that acts like a set of filters. It breaks data points down into facets like "Status" (Alive/Deceased), "Occupation" and "Affiliation." At the very bottom of the page, there are metadata tags that group the page into categories. This hybrid style is perfect for fans because it lets them navigate the show structure globally via hierarchy, but still filter down messy character attributes using facets. 

---

## Representation of Relationships

Relationships between resources are represented through a web of hyperlinks, "See Also" sections, and category indexes. 

The most common method is descriptive inline hyperlinks. When reading a character bio, any mention of another character, episode, or location is a clickable link that takes you straight to that specific resource's page. For example, Walter White's page directly links to Gus Fring's page within the text. 

Additionally, pages use a "See Also" section at the bottom to connect relevant topics that might not fit cleanly into the main body text. Finally, the wiki uses broad category pages at the very bottom of the screen. Clicking on a tag like "Deceased Characters" acts as an index, showing you every single resource on the wiki, that shares that specific status. This creates a highly connected network of information where no page feels like a dead end.
